# GT7 遥测事件检测器

GT7 POV 解说工具的**核心算法模块**。从遥测数据中检测驾驶事件，输出可直接喂给 LLM 的结构化复盘数据。

## 为什么这个模块最重要

整个项目的价值锚点是「**数字准确**」。AI 解说赛车视频时如果说错速度、圈速、方向，观秒就划走。所以架构上做了硬隔离：

```
遥测（事实）──> 事件检测（本模块）──> LLM（只负责组织语言）
                ↑ 数字只在这里产生
```

LLM 拿到的所有数字都是本模块算好的，它**不允许**自行计算或推测。这是零幻觉的架构保证。

## 检测的事件类型

| 类型 | 判定依据 | 置信度来源 |
|---|---|---|
| `collision` 碰撞 | 瞬时纵向 G < -2.2 | G 值绝对值 / 5.0 |
| `spin` 打滑 | 横向 G > 1.05 **且单轮**滑移率 > 0.14，持续 >0.4s | 横向 G / 1.8 |
| `hard_braking` 极限刹车 | 高速重刹且**平均减速度 > 4 m/s²** | 减速度 / 22.0 |
| `off_track` 出界 | 低速 + 滑移率 > 0.22 | 滑移率 × 4 |
| `heavy_throttle` 大油门 | 油门 >0.95 + 速度 >60 + 二档以上 | 固定 0.7 |

### 三个容易踩的坑（已在代码中修正）

**1. 打滑检测不能用四轮平均滑移率**

真实赛道上失控通常是「一侧轮胎失去抓地」，四轮平均值会把信号稀释到检测不出来。必须用 `max_slip()`（单轮最大值）。

**2. 极限刹车不能用「踏板深+ 持续久」判定**

长直道末尾的正常重刹也会持续好几秒。真正的极限刹车要用**减速度强度**（速度差/时间）判定，阈值 4 m/s² —— 低于这个只是普通刹车。

**3. 瞬时尖峰要过滤，事件要持续**

`filter_sustained()` 要求条件连续成立 >= min_duration，否则传感器噪声会被误报成事件。

## 输出格式

`export_report()` 产出：

```json
{
  "session": { "circuit": "...", "duration_s": 3600, "sample_rate_hz": 60.0 },
  "laps": [ { "lap": 5, "lap_time": 84.312, "is_best": true, ... } ],
  "best_lap": 5,
  "events": [ { "t_start": 1834.2, "type_cn": "极限刹车", "evidence": {...} } ],
  "event_summary": { "hard_braking": 12, "spin": 2 },
  "highlights": [ ... ]   // 按置信度×类型权重排序，可直接用于集锦剪辑
}
```

`highlights` 数组就是**集锦剪辑的时间轴**——每项都有 `t_start`/`t_end`，ffmpeg 直接按它切片即可。

`compare_laps(ref_lap, cmp_lap)` 是复盘功能的核心：按赛道坐标归一化后逐段对比两圈速度，输出「在哪个 10% 区段丢了多少时间」。

## 接真实数据

替换数据加载即可，本模块的算法不用动。三种数据源：

1. **UDP 实时**——GT7 广播 `33739`（轮速）/ `33740`（Addendum2 全字段），用 `gttelemetry` 库解码
2. **`.gtz` 回放文件**——`zetetos/gt-telemetry` 可读（`.gtz` 压缩 / `.gtr` 明文），用 `gttelemetry.Client(Scan())` 迭代
3. **gt7dashboard 录的 lap 文件**——该工具会自动保存你的每一圈

填充 `Sample` 字段时注意：`car_x`/`car_z` 是车身坐标，`compare_laps` 靠它们做赛道位置对齐，不能留 0。

## 阈值调整

`Thresholds` dataclass 里全部可调。接上真实数据后，**第一步应该是打印一轮的统计分布再定阈值**，别直接用默认值：

```python
print(f"横向G 分布: p50={...} p95={...} max={...}")
print(f"滑移率 分布: p50={...} p95={...} max={...}")
```

按分布的 p95 附近设阈值，比拍脑袋准。
