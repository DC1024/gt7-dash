# 部署与运维

## 两种部署方式

| 方式 | 适合 | 说明 |
|---|---|---|
| Docker Compose | 常驻服务器 / NAS | **推荐**。两个容器：`gt7-recorder`（收包）+ `gt7-dashboard`（Web） |
| Windows 免安装包 | 只想在游戏电脑上看 | Releases 里下载 `gt7-dash-windows-x64.zip`，双击两个 `.bat` |

两个服务都必须 `network_mode: host` —— GT7 用 UDP 广播发遥测，bridge 网络收不到。

## 首次部署

```bash
mkdir gt7-dash && cd gt7-dash
curl -O https://raw.githubusercontent.com/DC1024/gt7-dash/main/docker-compose.yml

# 🔴 这一步不能省
mkdir -p data && sudo chown 10001:10001 data

docker compose up -d
```

为什么要 `chown 10001`：镜像里的 `chmod` 会被 bind mount 遮住，
宿主机目录没授权的话，容器用户写不了文件 —— 表现是 `status.json` 静默失败、
录制器打不开 jsonl 直接退出。

## 升级

```bash
GT7_IMAGE=ghcr.io/dc1024/gt7-dash:v1.10.2 \
  docker compose up -d --no-deps --force-recreate gt7-recorder gt7-dashboard
```

🔴 **`--no-deps` 不能省**：不带它的话，动 dashboard 会连带重建 recorder，
正在跑的那场比赛会被切成两个文件（真实踩过，丢了 30 秒）。

🔴 **重启 recorder 后要重进赛道**：包类型在「进入赛道」那一刻锁定，
不重进的话会一直收不到数据（界面表现为「等待 PS5 进入赛道…」）。

校验：

```bash
curl http://<本机IP>:8787/api/health
# {"ok": true, "version": "1.10.2", "connected": true, ...}
```

`version` 对不上就是没生效 —— 常见原因是 `docker pull` 没拉下来，
compose 静默沿用了本地旧镜像。

## 仓库自带的部署脚本

```bash
tools/deploy.sh                    # 从 ghcr 拉 v<version> 并重启
tools/deploy.sh --no-restart       # 只拉镜像
tools/deploy.sh --local-build      # 服务器上现构建（离线兜底）
tools/deploy.sh --allow-dirty      # 工作区有改动也部署（不推荐）
```

脚本会：同步 `docker-compose.yml` → 拉镜像 → `up -d --no-deps --force-recreate`
→ 校验 `/api/health` 的版本号与仓库一致。工作区不干净时默认拒绝部署 ——
不然线上会跑着一个**不存在于任何 commit** 的版本。

## 数据目录

```
data/
├── 20261024_001041_unknown_6adb8701.jsonl     场次（每场一个文件）
├── 20261023_235630_unknown_6adb83ae.jsonl.gz  归档后的场次（无损，省 95%）
├── status.json          实时状态（接收器写、仪表盘读，schema 2 增量协议）
├── session_index.json   场次索引（最快圈等，重启不用重扫）
├── tracks.json          赛道库（指纹 / 名字 / BoP）
├── ref_lines.json       参考走线缓存
├── sessions_meta.json   收藏 / 改名
├── settings.json        回收站保留期 / 命名模板 / 事件阈值
└── _trash/              回收站
```

备份就备份整个 `data/` —— 除了容器镜像，所有状态都在里面。

## 排错

| 现象 | 先看这里 |
|---|---|
| 收不到数据 | PS5 与服务器同一网段？GT7 遥测上传开了？防火墙放行 UDP 33739/33740？ |
| 「包格式」在涨但「采样」为 0 | 车没开动。速度 ≥15 km/h 且 ≥30 帧才开始记录 |
| 一直「等待 PS5 进入赛道」 | recorder 重启过 → **退出赛道重新进一次** |
| 界面没有前轮转角 / 路面 | 用的是 A/B/`~` 包。默认是 C，检查 `GT7_PACKET_TYPE` |
| 历史场次列表转圈 | 老版本问题（每场都要完整解析 jsonl）。v1.6 起有 `session_index.json` + 预热 |
| 版本号对不上 | `docker pull` 没拉下来，compose 沿用了本地旧镜像 |
| 磁盘被日志吃满 | 容器已配 `max-size: 10m / max-file: 3`；还满就是场次数据，调自动归档天数 |

更细的数据流与模块边界见仓库里的
[docs/架构与运维.md](https://github.com/DC1024/gt7-dash/blob/main/docs/架构与运维.md)。

## 安全边界

- **只在内网用**。默认没有 API 鉴权，靠 Host 白名单 + 同站校验防跨站写入
- 不要把 8787 直接映射到公网。要远程看就上 WireGuard / Tailscale 之类
- 数据全部本地处理，不调用任何云端服务（可选的大模型润色是另一个项目
  gt7-coach 的可选功能，不填 key 就完全不外呼）
