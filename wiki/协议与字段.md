# 协议与字段

这一页是「GT7 的 UDP 包里到底有什么」的**实测结论**，不是社区文档的转抄。
所有偏移都在真机上验证过（GT7 ver.01.720）。

## 1. 四种包格式

GT7 用**心跳字符**决定发哪种包。客户端每 5 秒往 `33739`（或 `33740`）发一个字符，
PS5 就按那个格式回包。本项目 `--packet-type` 改的就是这个字符。

| 格式 | 长度 | 说明 |
|---|---|---|
| `A` | 296 B | 基础包，GT7 < 1.68 只有这个 |
| `B` | 316 B | A + 5 个 float（方向盘转角/角速度、sway、?、surge） |
| `~` | 344 B | **解不开**，见下文 |
| `C` | 368 B | GT7 1.68+，**A 和 B 的超集** |

🔴 **包类型在「进入赛道」那一刻锁定**。在赛道里改心跳字符完全不生效 ——
实测在赛道里依次换 A→`~`→B→C 各 90 秒，四段收到的**全是 296B 的 A 包**；
先发新心跳、再退出赛道重新进，立刻变成新格式。

### C ⊃ B ⊃ A

11436 帧真实 B 包与 21175 帧真实 C 包对拍：**B 独有的那 5 个 float，C 里一个不少**，
数值分布一致。所以「想要三轴加速度」不需要切 B —— 切 B 反而会丢掉路面和前轮转角。

## 2. 解密

- 密钥：`b"Simulator Interface Packet GT7 ver 0.0"[:32]`
  （注意：源码里是 38 字节的字符串，Go 的 `[32]byte(...)` 会**截断成前 32 字节**，
  任何非 Go 移植都必须照着截）
- 算法：Salsa20/20，nonce 8 字节 + counter 8 字节（**顺序照 Go，不是照 spec**）
- IV：藏在**密文**的 `0x40`（`u32` 小端）

nonce 的推导规则**两套**，靠 magic（`0x47375330` = `"GT7\0"`）自己判断：

```
A / B / ~ :  nonce = LE32(iv1 ^ 0xDEADBEAF) || LE32(iv1)
C         :  nonce = LE32(iv1 ^ 0xDEADBEEF) || LE32(iv1)
```

就差 `AF` 和 `EF` 两个字母。用 A 的规则去解 C 包，10783 个一个都解不开；
换一个字母，全部解开。

## 3. 字段偏移表（实测）

前 296 字节所有格式共用（节选）：

| 偏移 | 字段 | 说明 |
|---|---|---|
| `0x00` | magic | `0x47375330` |
| `0x04` | position[3] | 世界坐标，y 向上 |
| `0x10` | velocity[3] | m/s |
| `0x2C` | angVel[3] | 角速度，`0x30`（y）是横摆角速度 |
| `0x3C` | engineRPM | float |
| `0x4C` | speed | **m/s**（×3.6 得 km/h） |
| `0x60` | tyreTemp[4] | ℃，FL/FR/RL/RR |
| `0x74` | lapCount | u16，菜单态是 `0xFFFF` |
| `0x78` / `0x7C` | bestLap / lastLap | **毫秒**，`0xFFFFFFFF` = 无 |
| `0x84` | qualiPos | **比赛中就是当前名次** |
| `0x8E` | flags | bit0 在赛道 / bit1 暂停 / bit2 加载 / bit3 在档 |
| `0x90` | gear | **位域**：低 4 位当前档、高 4 位建议档（`0xF2` → 2 挡） |
| `0x91` / `0x92` | throttle / brake | u8，÷255 |
| `0xA4` | wheelSpeed[4] | rad/s，FL/FR/RL/RR |
| `0x124` | carCode | u32 |

296 之后是扩展段（**只有 B / C 有，A 读到这里就是越界**）：

| 偏移 | 字段 | 单位 | 实测 / 备注 |
|---|---|---|---|
| `0x128` | steeringWheelAngle | rad | 峰值 ±2.6（±150°），是前轮的 ~15 倍（转向齿比） |
| `0x12C` | steeringAngularVelocity | rad/s | 与 `0x128` 的差分相关 +0.99 |
| `0x130` | **sway** | m/s² | 横向加速度，**正 = 右转** |
| `0x134` | heave？ | m/s² | **含义未定**：与 angVel_x 相关 +0.95、压路肩反而变小 → 不导出 |
| `0x138` | **surge** | m/s² | 纵向加速度，正 = 加速、负 = 刹车 |

368 字节独有（格式 C）：

| 偏移 | 字段 | 说明 |
|---|---|---|
| `0x158` | **surfaceType[4]** | **4 个 ASCII 字符**，FL/FR/RL/RR：`T` 铺装 `C` 路肩 `G` 草地 `s` 砂石（小写） |
| `0x160` / `0x164` | wheelSteeringAngle[2] | 左右**前轮**转角，rad，±0.17（±10°），**正 = 左转** |
| `0x168` | wheelBase | 轴距，m（实测 2.890~2.907） |
| `0x16C` | carCategory | ASCII 组别，如 `GR1` / `GR3` / `GRN` |

### 路面字符的实测分布

21175 帧真实 C 包（其中一段是故意跑草地 / 压路肩）：

| 值 | 含义 | 占比 |
|---|---|---|
| `TTTT` | 铺装 | 90.2% |
| `GGGG` | 草地 | 5.5% |
| `TCTC` / `CTCT` | 压右侧 / 压左侧路肩 | 1.5% / 1.0% |
| `CCCC` | 四轮全在路肩 | 0.2% |

`TCTC` 与 `CTCT` 成对出现，正好对应「一侧压路肩」的几何关系 —— 反过来印证了
四轮顺序是 FL/FR/RL/RR（与胎温一致）。拉力赛道整场都是 `ssss`。

## 4. 符号约定（最容易搞错的地方）

| 量 | 正值含义 | 怎么验证的 |
|---|---|---|
| `g_force[1]`（横向 G） | **左转** | ① `corr(dθ/dt, ω_y) = −0.93` → GT7 是右手系；② `corr(横向 G, 右轮速−左轮速) = +0.40`，左转时右侧走外圈、轮速更快 |
| `sway` | **右转** | 与横摆角速度相关 −0.92（与横向 G 反号） |
| `surge` | 加速 | 全油门均值 +4.4~5.2、刹车 −20~−21 m/s² |
| `steer_angle_l/r`（前轮） | **左转** | 与横摆角速度相关 +0.85 |
| 横摆角速度 `0x30` | 左转 | 右手系里绕 +y 正向旋转 = 逆时针俯视 = 左转 |

🔴 **G 力球把正的横向 G 画在右边**，所以「左转时球往右漂」是对的 ——
球画的是**离心方向**（你被甩向弯外的那一侧），和界面那个「碗」的比喻一致。
别看到球往反方向跑就去翻符号：一翻，G-G 图、事件里的曲率、转角的符号会跟着全错。

## 5. `~` 包（344B）：确认存在，但解不开

- 抓到 11945 个 344B 包，发往 `33739`、60Hz、互不相同 → 确实是 GT7 遥测
- 长度**确认 344**（项目早期注释写 332 是错的）
- 用任何已知规则都解不开：`tools/brute_tilde.py` 扫了
  「IV 偏移 0…336 × 16 个 mask × nonce 两种顺序 × 密文起始 0/4/8」，magic 零命中
  → 它换了 key，或换了 nonce 的来源，不是改个常量能对齐的
- 收益也很小：相比 A 只多 `energyRecovery`（混动 / 电车才非 0）和 `throttleFiltered`
- **决定不做**。选 `--packet-type ~` 时启动横幅会直接警告，而不是让你对着
  「等待 PS5 进入赛道…」转圈

## 6. GT7 确实不提供的东西

以下不是"没做"，是**协议层根本没有**：

- 其他车辆的位置 / 速度 / 身份（只能从名次变化间接推断）
- 胎压 / 磨损（胎温有，但那是表面温度）
- 赛道名、天气、积水率、BoP
- 赛道中心线 / 参考线（本项目的参考走线是自己算出来的）

## 7. 方法论：怎么把字段挖出来

这套流程比结论更值钱，下次协议再变能复用：

1. **先拿原始包，别先解析** —— `tools/capture_raw.py` 只存加密 hex，不猜字段
2. **用两个已知状态做逐字节对拍**：草地停车段 vs 铺装行驶段，只有真正随状态变的
   字节会浮出来（路面 `0x158` 就是这么找到的）
3. **类型别信文档**：`surfaceType` 文档写 `int32[4]`，实际是 4 个字符 ——
   按整数扫永远对不上，这就是"全 0"结论的来源
4. **派生量用语义验证，别看相关系数**：加速度用"全油门均值 vs 刹车均值"判，
   比跟速度差分算相关可靠得多（速度量化 0.1 m/s，差分噪声 6 m/s²）
5. **拿不到的就说拿不到**：`0x134` 至今含义未定，宁可空着也不导出
